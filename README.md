# gogate

Легковесный API Gateway и Reverse Proxy на Go. 

Проект написан для практики работы с сетевым стеком и примитивами синхронизации без использования сторонних веб-фреймворков (только стандартная библиотека `net/http`, `yaml.v3` для конфига и `golang.org/x/time/rate` для лимитера).

## Схема работы

```text
                  +-------------------+
                  |   Клиент (HTTP)   |
                  +---------+---------+
                            |
                            v
                  +-------------------+
                  |   Rate Limiter    | <--- Token Bucket (по IP)
                  +---------+---------+
                            |
                            v
                  +-------------------+
                  |   Reverse Proxy   | <--- Роутинг по префиксу пути
                  +---------+---------+
                            |
             +--------------+--------------+
             | Балансировка (Round-Robin)  | <--- Фоновый TCP Health Check
             +--------------+--------------+
                            |
            +---------------+---------------+
            |                               |
            v                               v
  +-------------------+           +-------------------+
  |  Backend 1 (:8081)|           |  Backend 2 (:8082)|
  +-------------------+           +-------------------+
```

## Что реализовано под капотом

* **Reverse Proxy (`net/http/httputil`)** — проксирование трафика на группу апстримов в зависимости от префикса URL.
* **Lock-free балансировка (`sync/atomic`)** — распределение запросов по алгоритму Round-Robin. Выбор следующего инстанса происходит через атомарный инкремент счетчика без блокировки горутин мьютексами.
* **Активные Health Checks (`net.DialTimeout` + `sync.RWMutex`)** — фоновая горутина раз в 5 секунд проверяет доступность бэкендов по TCP. Если узел падает, он временно исключается из ротации, пока снова не поднимется. Использование `RWMutex` позволяет не блокировать чтение статуса при большом потоке запросов.
* **Rate Limiting (`sync.Mutex` + Token Bucket)** — защита от спама на уровне middleware. Ограничивает количество запросов с одного IP-адреса (по умолчанию: 2 RPS с допустимым всплеском до 5 запросов). При превышении отдает `429 Too Many Requests`.
* **Graceful Shutdown** — перехват сигналов `SIGINT` / `SIGTERM`. При остановке сервер перестает принимать новые соединения и ждет до 5 секунд, чтобы корректно завершить текущие запросы.
* **Структурированное логирование (`log/slog`)** — все события (проксирование, падение нод, блокировки по лимитам) пишутся в `stdout` в формате JSON.

## Структура проекта

```text
├── cmd/gateway/main.go       # Точка входа, инициализация сервера и Graceful Shutdown
├── internal/
│   ├── balancer/balancer.go  # Round-Robin и фоновые проверки здоровья (Health Checks)
│   ├── config/config.go      # Парсинг YAML-конфигурации
│   ├── middleware/           # HTTP-middleware (Rate Limiter)
│   └── proxy/proxy.go        # Маршрутизация и проксирование запросов
└── config.yaml               # Конфигурация маршрутов и апстримов
```

## Конфигурация

Маршруты и список целевых серверов задаются в файле `config.yaml`:

```yaml
listen_addr: ":8080"
routes:
  - path: "/api1"
    backends:
      - "http://localhost:8081"
      - "http://localhost:8082"
  - path: "/api2"
    backends:
      - "http://localhost:8083"
```

## Как запустить и протестировать локально

### 1. Поднимаем тестовые бэкенды
В разных вкладках терминала запустите пару простых HTTP-серверов (например, через Python):

```bash
python3 -m http.server 8081
python3 -m http.server 8082
```

### 2. Запускаем шлюз

```bash
go run cmd/gateway/main.go
```

### 3. Проверяем сценарии

**Балансировка нагрузки:**
Сделайте несколько запросов подряд — в логах шлюза будет видно, как они по очереди уходят на порты `8081` и `8082`:

```bash
curl -I http://localhost:8080/api1
```

**Отказоустойчивость (Failover):**
Остановите один из Python-серверов (`Ctrl+C`). В течение 5 секунд в логах появится предупреждение `"Backend is DOWN"`, и весь трафик без ошибок для клиента пойдет на оставшийся живой сервер.

**Rate Limiter:**
Отправьте серию быстрых запросов в цикле. После первых 5 запросов шлюз начнет отбивать трафик с кодом `429`:

```bash
for i in {1..10}; do curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api1; done
```
